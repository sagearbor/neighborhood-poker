## What this repo is

A **Google Sheets** tournament manager for "Pro-Am Concurrent Flight" poker nights — not a typical app. There is no server, no UI framework, no test suite. The deliverables are:

1. A Google Sheet (the actual product users interact with) generated by Python scripts hitting the Sheets API.
2. Google Apps Script files that get pasted into the sheet's bound script editor to add a blinds-timer dialog.
3. Markdown docs and a one-pager PDF that explain the format.

## Running the scripts

```bash
pip install google-auth google-auth-oauthlib google-api-python-client

# One-time: authorize with all required scopes (spreadsheets, drive, script.projects)
python3 setup_auth.py

# Build the original "Concurrent Flight" sheet (whales can win main pot)
python3 create_sheet.py [--no-timer-install]

# Build the "Separate Prize Pools" variant (Fish/Whale pots walled off)
python3 create_sheet_separate_pools.py [--no-timer-install]

# Build the "Multi-Tier" variant (configurable 2-6 separate pots)
python3 create_sheet_multi_tier.py [--no-timer-install]

# Update only the Blinds Timer tab on the original (hardcoded) sheet
python3 update_blinds.py
```

## Architecture

### Domain concept (load this before changing formulas)

"Pro-Am" means two buy-in tracks share the same table and chip stack:
- **Low / Fish** — base buy-in (default $40)
- **High / Whales** — `base × multiplier` (default 4× = $160)

Every player's base $40 feeds the **Main Pot** (everyone competes). Whales' extra $120 feeds the **Side Pot** (whales only). Both tracks pay a flat **Bounty** ($10) per buy-in/rebuy.

Buy-in/multiplier/bounty/top-off/max-rebuys/rake live in **Settings!B2:B7** and are referenced by absolute cell address from formulas elsewhere. Renaming or reordering those rows breaks the entire sheet.

### Sheet layout (created by `create_sheet.py`)

Six tabs with fixed `sheetId` constants `SID_SETTINGS=0 … SID_BLINDS=5`:

- **Settings** — inputs in B2:B7, calculated values in B9:B14, payout-tier table in A17:H21 (5 tiers keyed off total-player count, paying 1–5 places).
- **Registration** — header row + 30 player rows (rows 2–31, `FIRST_PLAYER_ROW`/`LAST_PLAYER_ROW`). Columns A–E are user inputs (name, track dropdown, buy-in checkbox, rebuy count 0–2, top-off checkbox). Columns F–I are formulas generated by `reg_formulas(r)` that compute Total Cash, Main Pot, Side Pot, Bounty per row. Conditional formatting colors Low rows blue, High rows gold.
- **Dashboard** — summary in B3:B13, Main Pot payout table in rows 15–19 (with chart-helper columns E–G), Side Pot payout table in rows 23–26. Payout % cells use nested `IFS(...)` against the Settings tier table; total-player count for Main Pot lookup is `$B$3`, whale count for Side Pot lookup is `$B$5`.
- **📺 Live Payouts** — empty grid with a column chart whose data ranges point back into Dashboard rows 14–19 cols E–G. Created by `make_chart_request()`.
- **Instructions** — static text block.
- **⏱ Blinds Timer** — stub initially, replaced by `update_blinds.py` with a real schedule (see below).

### Cross-file coupling to watch

- Formula generators in `create_sheet.py` (`reg_formulas`, `build_dashboard_data`) hardcode `Settings!$B$2`, `$B$3`, `$B$4`, `$B$5`, `$B$7` and the payout tier rows 17–21. Any structural change to Settings must update those references.
- The Dashboard chart's source ranges in `make_chart_request()` are tied to specific Dashboard row indices (14–20, cols 4–7). Inserting rows into the Dashboard layout will silently break the chart.
- The Apps Script timer (`apps-script/blinds_timer.gs`) reads from the `⏱ Blinds Timer` tab starting at `DATA_START_ROW = 7` (1-indexed), columns A–E. `update_blinds.py` writes that exact layout: rows 1–4 are settings/instructions, row 6 is the header, row 7 onward is `Level | SB | BB | Ante | Duration | Elapsed`. Break rows are detected by the literal substring "BREAK" in column A. Keep the row 7 contract and the BREAK keyword in sync across both files.

### Apps Script timer

`apps-script/blinds_timer.gs` + `apps-script/timer_dialog.html` are auto-deployed by `apps_script_installer.install_timer`, which creates a **container-bound** Apps Script project on the target spreadsheet via the Apps Script API (`projects.create` with `parentId=spreadsheet_id`, then `projects.updateContent` to upload the two source files plus an `appsscript.json` manifest). The bound script's `onOpen` is a simple trigger and adds the `🃏 Poker Timer` menu without user authorization; clicking Start Timer triggers the standard Apps Script auth prompt the first time. The `.gs` file reads the schedule from the sheet at runtime, so editing the schedule in `⏱ Blinds Timer` tab still propagates to the timer on next start. The manual copy-paste flow in `BLINDS_TIMER_SETUP.md` is now the fallback, used only when the API/scope isn't available.

## Conventions specific to this repo

- The script files use a "build pure data, then apply" pattern: each tab has a `build_*_data()` returning rows of values, and `make_format_requests()` returns batchUpdate requests. Keep new logic in that shape rather than interleaving API calls.
- Track display names use emoji + word pairs (🐟 Fish / 🐋 Whales is current; alternates listed in `track-names.md`). The user has explicitly preferred "whale" over "shark" in copy (see commit `64fe9da`).
- `The Pro-Am Poker Night.pdf` is a regenerated artifact of `one_pager_pitch.md`. When the pitch copy changes, regenerate the PDF too.
